# Repository audit — 13 November 2026

## Scope and method

Reviewed the tracked application, examples, specification pipeline, generated
service implementation, Studio, design and story tooling, shared UI, test
infrastructure, package scripts, CI, and operating documentation. The starting
checkout contained 292 tracked files. Dependency and generated directories are
outputs, not separately maintained source. Existing changes to `AGENTS.md`,
`README.md`, the skill links, `spec.ts`, and `selftest.ts` were preserved.

The original fixes were captured in `9fda5d0`. A separate chat then integrated
new upstream work as `11feb73`; the final pass checks that integration, which
contains 303 tracked files. Its new test architecture supersedes the original
conformance callback and screenshot implementations. The report distinguishes
those replacements from the original fixes.

This is an evidence-based audit, not a claim that every possible bug has been
eliminated. Findings below distinguish demonstrated faults from optional
cleanup. Verification uses Node 26 and the existing repository commands;
acceptance remains the user's decision.

The assistant queue changes the saved-state schema. Older JSON without
`pending` and `delivered` is refused, rather than silently treated as having no
unfinished work. No existing user file was changed. External delivery requires
the provider to honor the idempotency number; the included scripted provider
demonstrates this contract, and there is no live payment integration.
Persistence supports one process per file; there is no cross-process lock.
The driver-import diagnostic resolves statically knowable paths. A path
computed from runtime data still needs review; this diagnostic is not an
isolation boundary for arbitrary untrusted code.

## Rules, proofs and journeys

The assistant adds the story “Deliver promised effects after a restart,”
with five rules covering queue preservation, numbered acknowledgements,
nonnegative delivery counts, valid queued actions and reachable delivery
states. The audit discovered that a persisted queue also needs validation:
otherwise a structurally valid saved file could schedule an invalid action.
Existing state, choice and confirmation rules now include the persisted queue.

Studio adds “Inspect a component and its stories,” with a generated selection
machine, valid-index invariant and reachable empty/later-story cases. Repeated
refreshes of an unchanged catalog preserve selection and draft prop overrides.
The three example entry documents add navigation only. Fullstack's equality
and removal rewrites preserve rule meaning; dashboard's weights affect only
simulation. The audit preserves the existing behavioral requirements.

The integrated greeter adds the discovered rule “The number of greetings is
never negative.” Its reload journey demonstrated that a negative saved count
was previously accepted; the new invariant rejects that unreachable state.

The upstream integration additionally consolidates the fullstack server's
separate edit/refusal transitions into one request transition. It now decides
acceptance from the edit and current list, matching the HTTP shell, and the
system model calls that transition. Its three state invariants remain; the
combined request law replaces separate helper laws. These are upstream model
changes, rather than a workaround for a failing audit proof.

Hand proofs changed in:

- `vibestack/examples/assistant/spec/assistant.proof.dfy`: queue-preserving
  choice, confirmation and acknowledgement, including submission counts for
  concatenated and shortened queues.
- `vibestack/studio/spec/components.proof.dfy`: catalog loading and component
  selection preserve valid selected positions.
- `vibestack/examples/fullstack/spec/system.proof.dfy`: obsolete equality and
  removal induction was eliminated. The now-unneeded
  `spec/todo.proof.dfy` was removed; its law remains and proves directly.

Existing journeys were extended for state-reference isolation, both delivery
crash windows, malformed saved queues, private storage, stalled HTTP replies,
Studio edits during publication, catalog refresh/selection, disabled child
buttons, portable property-test replay and CLI generation/watch behavior.
These exercise shell, browser, filesystem or tool boundaries rather than
repeating only the model's rules.

## Cleanup and consolidation

The original audit proposed the following nine tests for removal because they
repeat generated behavior without crossing an application boundary. This chat
did not delete them. The separate upstream integration has since replaced
their files with consolidated real-service journeys and conformance drivers.

In `vibestack/examples/fullstack/test/client.test.vibe`:

- “an edit shows at once and waits in the queue”
- “an acknowledgement takes the edit out of the queue and brings the server's list”
- “an older copy of the list is ignored”
- “a refused edit leaves the queue and is counted once”
- “edits made offline queue up, and the page hears nothing until it is back”
- “edits the rules do not allow change nothing”
- “a confirmed copy that already holds a queued edit shows it once”
- “a batch of pushes is drained in order and keeps the client's rules”

In `vibestack/examples/assistant/test/assistant.test.vibe`:

- “an event cannot say who sent it”

The mutable-reference assertions now run through the durable assistant and
fullstack services, and the generated service remains covered by the tooling
selftest. No additional test deletion is proposed.

The original blank `apps/app` was intentional template scaffolding. The
upstream integration fills it with a hello-world example. Standalone examples
remain outside the workspace and are included in this audit's local checks;
that packaging decision is not reported as a defect.

Fullstack's generic helper laws remain necessary: they preserve arbitrary
operation fields used by retry identity, while named transitions normalize
those fields. Its to-do list is deliberately anonymous; random client IDs
prevent accidental collisions but do not authenticate a person. The model
explicitly includes forged requests. Convergence is reachable, not guaranteed
when the network can keep losing messages forever.
